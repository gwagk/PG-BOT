# IT Competency × PG-BOT — Presentation Source

## Core message
**Policy → Competency → Action**

การปฏิบัติตามนโยบายที่ดี ไม่ใช่เพียงทำตามคำสั่งให้ครบ แต่ต้องเข้าใจวัตถุประสงค์ ประเมินความเสี่ยง เลือกวิธีที่เหมาะสม และตรวจสอบผลได้

---

## Slide 1 — IT Competency: ทำไมต้องมี?
**On slide**
- ใช้คอมพิวเตอร์ทุกวัน ≠ มี IT Competency
- รู้ → ทำได้ → ตัดสินใจเป็น
- ดูแลสิ่งที่อยู่ในความรับผิดชอบของเรา

**Speaker script**
ทุกวันนี้เราใช้คอมพิวเตอร์ทำงานแทบทุกวัน แต่คำว่า “ใช้เป็น” ไม่ได้แปลว่าเราดูแลมันเป็น หรือรับมือเมื่อมีความเสี่ยงได้ IT Competency ในความหมายที่อยากชวนคุยวันนี้จึงง่ายมาก: รู้ว่ากำลังทำอะไร ทำสิ่งพื้นฐานได้ และตัดสินใจได้ว่าอะไรควรทำเอง อะไรควรหยุด และเมื่อใดควรขอความช่วยเหลือ

---

## Slide 2 — Pain ไม่ใช่ “ไม่รู้”
**On slide**
> **Pain: รู้ แต่ไม่ได้ทำอย่างสม่ำเสมอ**

ไฟฟ้า • ฝุ่น • ความร้อน • ความชื้น • น้ำ • อาหาร/แมลง • Password • Software • Update

**Speaker script**
ข้อควรปฏิบัติมีเยอะมาก เราพูดไม่หมด และไม่จำเป็นต้องเทศน์ทุกข้อ เพราะทุกคนรู้อยู่แล้วว่าของที่ใช้ทุกวัน ถ้าไม่ดูแล ไม่นานก็เสื่อมและพัง Pain ของเราจึงไม่ใช่ไม่รู้ แต่คือรู้แล้วไม่ได้ทำอย่างสม่ำเสมอ

---

## Slide 3 — Security starts with us
**On slide**
**ความปลอดภัยเริ่มจากตัวเราเอง**
- รับผิดชอบเครื่องมือที่เราใช้
- ร่วมมือกับ IT Policy
- ไม่รู้ = ไม่เดา
- ไม่แน่ใจ = หยุดตรวจสอบ

**Speaker script**
Firewall หรือฝ่าย IT ไม่สามารถป้องกันทุกอย่างได้ ถ้าจุดปลายทางไม่ดูแลตัวเอง ความปลอดภัยขององค์กรจึงเริ่มจากผู้ใช้แต่ละคน และจากความร่วมมือกับนโยบาย IT ขององค์กร เมื่อแต่ละจุดรับผิดชอบตัวเองได้ ภาพรวมจึงแข็งแรงขึ้น

## Slide 4 — จาก Policy สู่ Action
**On slide**
### POLICY → COMPETENCY → ACTION
นโยบายบอก “ต้องการอะไร”  
Competency ทำให้เข้าใจ “ทำไมและทำอย่างไร”  
Action คือ “ลงมืออย่างเหมาะสมและตรวจสอบผล”

**Speaker script**
หนังสือสั่งการไม่ควรถูกอ่านเป็น checklist แล้วไถตามให้ครบ เราต้องตีความวัตถุประสงค์ก่อน แล้วเลือกวิธีปฏิบัติที่เหมาะสม นี่คือความต่างระหว่างทำตามคำสั่งกับการทำงานด้วย Competency

## Slide 5 — วิธีคิดที่ใช้ได้จริง
**On slide**
**5ส** — จัดสภาพแวดล้อมให้พร้อม  
**Lean** — ตัดสิ่งที่ไม่สร้างคุณค่า  
**PDCA** — ทำแล้วตรวจและปรับ  
**Pilot mindset** — ดูสถานการณ์ → ตัดสินใจ → ลงมือ → ตรวจผล

**Speaker script**
เราไม่ต้องเรียนทฤษฎีใหม่ทั้งเล่ม ใช้แก่นที่จำเป็นพอ 5ส ช่วยจัดสภาพแวดล้อม Lean ช่วยตัดงานสูญเปล่า PDCA ทำให้ไม่จบที่การลงมือ แต่ต้องตรวจผล และวิธีคิดแบบนักบินเตือนว่า ก่อนลงมือให้ดูสถานการณ์ ตัดสินใจ แล้วติดตามผลเสมอ

## Slide 8 — PG-BOT ทำอะไร / ไม่ทำอะไร
**On slide**
**DO**
- ทำความสะอาด User Temp
- Verify หลังทำงาน
- เก็บ Receipt ล่าสุด 1 ไฟล์

**DO NOT**
- ไม่ขอ Admin
- ไม่แตะ Personal files
- ไม่ปิด Windows Update / Defender / Firewall
- ไม่ถอนโปรแกรม
- ไม่ส่งข้อมูลออก

**Speaker script**
เราเจตนาทำให้ขอบเขตเล็ก เพราะยิ่งสิทธิ์น้อยและขอบเขตชัด ยิ่งตรวจสอบง่าย PG-BOT ทำเพียงงานที่ตกผลึกแล้วว่าเหมาะกับ Automation ส่วนเรื่องที่ต้องใช้วิจารณญาณยังเป็นหน้าที่ของผู้ใช้
